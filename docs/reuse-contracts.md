## Budget boundary

KRE's own bound covers the context it emits. In the embedded tool-loop case documented by OpenClaw, `assemble` receives a history allowance that already reserves room for pending user and tool messages. OpenClaw's model fields distinguish native capacity (`contextWindow`), active-input cap (`contextTokens`), and output allowance (`maxTokens`). M2 will specify the measurement unit and stage for an offline packet. Exact byte accounting or a supplied estimator cannot establish the installed renderer and provider token count. [KRE context contract][kre-context] · [OpenClaw context engine][openclaw-engine] · [OpenClaw model configuration][openclaw-budget]

## Existing implementations and manifest evidence

- [Lossless Claw at `15548bfcdd76dbf05365f3c82637fc81b8cf5f67`][lossless] already archives messages and uses model-generated summaries in an OpenClaw context engine. Its archive and inference are outside this fixture-based operation projection. [LangGraph persistence][langgraph] and [Temporal event history][temporal] recover state for workflows they run. The M1 input is observational and recovery must leave the observed tool untouched, so the stdlib JSONL reader and SQLite transaction are sufficient.
- The KRE [public source manifest][kre-manifest] matched SHA-256 for the ten reviewed manifest, schema, fixture, documentation, and continuity implementation files. The [context digest manifest][kre-contract-manifest] agrees with the public source manifest on the two schemas and two fixtures. AFR's [release][afr-release] resolves to the reviewed commit and lists an asset digest manifest. AFR distribution artifacts were outside this source review.
